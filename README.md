# 🏟️ The LLM Arena: Multi-Agent Prop Firm Trading System Experiment

Welcome to **The LLM Arena**. This repository documents a comprehensive experiment to determine whether multiple Large Language Models (LLMs) can collaboratively design, critique, and optimize a highly robust, prop-firm-compliant algorithmic trading system.

## 📜 The Premise
I created a strict set of guidelines for building a prop-firm-compliant Forex trading Expert Advisor (EA). These guidelines were given to four distinct LLMs:
1. **Qwen**
2. **Claude**
3. **DeepSeek**
4. **ChatGPT**

Each LLM was tasked with independently creating a complete trading system that strictly follows the provided guidelines. 

## 📂 The Rules of the Arena
To ensure a fair and structured experiment, the following rules apply:
* **Isolated Workspaces:** Each LLM has been assigned its own dedicated folder in this repository to store its version of the system.
* **Read-Only Peer Access:** The LLMs are allowed to read and analyze the code and documentation in the other folders.
* **Strict Immutability:** They are **strictly forbidden** from altering, deleting, or modifying the files in any folder other than their own. They can only write to their own designated directory.

---

## 🗺️ The Experiment Phases

### Phase 1: Independent Development (Version 1)
Each LLM builds its system from scratch based solely on the initial prompt and guidelines. This results in four distinct Version 1 codebases.

### Phase 2: Blind Testing & Scoring
Once all four LLMs have completed their V1 builds, the systems will be subjected to a simulated environment using **NautilusTrader** as the testing engine. 
* The systems will be tested blindly.
* Results will be scored based on individual component performance and overall system metrics.
* These raw performance scores will be kept private until the final synthesis phase.

### Phase 3: Peer Review & Synthesis (Version 2)
Each LLM will review all four codebases and write a detailed report justifying which components they would select to build a synthesized **Version 2** of the system.
* **The Voting Matrix:** Every time an LLM selects a specific component from any of the 4 codebases, that component receives **1 point**.
* **Combined Scoring:** These "Peer Vote" points will be combined with the private "NautilusTrader Performance" scores from Phase 2.
* **Tie-Breaker:** In the event of a tie for a specific component, a secret vote will be taken among the LLMs. The highest-voted component wins.
* The components with the highest combined scores will be merged into the **Version 2** codebase.

### Phase 4: Final Testing & Optimization (Versions 3 & 4)
* **Version 3:** The synthesized V2 system will be put back into the NautilusTrader simulation to test how the "Frankenstein" merge performs compared to the original standalone builds.
* **Version 4 (The Final Build):** The LLMs will analyze the V3 test results. Working in a combined effort, they will correct any errors, optimize the system for long-term stability, and compile the final **Version 4**. 

### 🏆 The Ultimate Goal
Version 4 will be deployed to attempt a **real $100,000 Prop Firm Challenge**.

---

## 🧠 Objective
The core purpose of this experiment is to answer two questions:
1. Can multiple LLMs work together to create a superior, unified version of a complex system compared to their individual efforts?
2. What are the specific strengths and weaknesses of each LLM when tasked with quantitative finance, risk management, and systems architecture?
